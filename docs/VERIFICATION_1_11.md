# 1〜11단계 실측 기록 절차

작전실의 한 표는 `public/verification-plan.mjs`의 저장소 기준 41개 항목을 사용합니다.
심판의 공식 항목표가 제공되지 않아 동일한 41종인지 검증하지 않았습니다. 항목별 대응 확인 전
이 표의 건수를 심판 점수나 심판 통과 건수로 사용하지 않습니다.

현재 실제 결과 수집·검증 저장소는 미연결입니다. 표의 모든 행은 미실행이며 실측·통과는 0입니다.
요약 API 호출 성공, 과거 사용자 확인, 로컬 대역·합성 시험을 개별 실측 결과로 옮겨 적지 않습니다.

## 실행 순서

1. 제출 커밋과 배포 응답의 커밋을 대조합니다. 공식 41종 표가 있다면 먼저 현재 체크리스트와 대응을 확인합니다.
2. A/B 로그인과 관리자가 승인한 시험 접속을 준비합니다. 기존 네 메모·복구 대상·다른 작업은 보존합니다.
   추가·수정·삭제 및 교차 소유자 쓰기 시험은 별도로 승인한 폐기용 가상 메모에만 합니다.
   대상과 승인이 준비되지 않으면 해당 시험을 미실행으로 남깁니다.
3. 단계 순서대로 정상 허용과 금지 거부를 각각 요청합니다. 3단계 삭제 후 GET 404처럼 상태 확인 요청도
   분리합니다. 금지 결과가 허용되면 그 첫 실패를 기록하고 다음 위험한 시험으로 진행하지 않습니다.
4. 브라우저 Network 또는 공식 운영 API·서버 기록에서 아래 최소값만 추출합니다.
   HAR·원문 로그·응답 전체를 내보내지 않습니다. Cookie·Authorization·비밀번호·토큰·메모 ID/본문·실명은 복사하지 않습니다.
5. 응답의 서버 요청 ID와 서버 기록의 요청 ID를 대조합니다. 엔진의 `requestId`는 해당 응답에서 그대로
   확인하고, HTTP 경로는 공식 응답 추적 ID(예: 실제 응답에 있는 `x-vercel-id`)를 서버 기록과 대조합니다.
   없는 ID를 생성하지 않습니다. 승인 API의 `requestId`는 승인 신청 번호이며 시험 요청 추적 ID가 아닙니다.
   작전실 요약의 `recordId` 역시 요약 한 건의 번호이므로 41종 요청의 ID로 복사하지 않습니다.
6. 확인 시각은 해당 응답을 받은 시각을 시간대가 있는 ISO 형식으로 기록합니다. 응답 Date와 서버 기록
   시각을 함께 대조하고 불일치하면 확인 불가로 남깁니다. 예상 시각이나 과거 시험 시각을 채우지 않습니다.
7. 응답과 가린 서버 기록이 함께 확인된 결과만 다음 열에 반영할 수 있습니다. 현재는 이 영수증을
   검증·저장하는 운영 연결이 없으므로 UI에는 미실행만 표시합니다. 브라우저 입력이나 localStorage로
   실제 결과·통과 수를 덮어쓰는 기능은 두지 않습니다.

| 필드 | 기록할 값 |
|---|---|
| 단계·시험 | 체크리스트 ID와 시험 종류 |
| 구분·기대 결과 | 정상 허용 또는 금지 거부, 기대 HTTP/고정 사유·일치 여부 |
| 실제 API 결과 | 실제 HTTP 상태·고정 사유·검증 일치 여부만. 자료 본문 제외 |
| 요청 ID | 해당 응답과 서버 기록에서 동일하게 확인한 추적 번호 |
| 확인 시각 | 해당 응답 수신 시각, 시간대 포함 ISO |
| 증거 종류 | 실제 HTTP / 운영 엔진 / 로컬 가상 / 대역 / 수동 화면을 구분 |
| 판정 | 미실행 / 확인 불가 / 실패 / 실측 통과 |

## 판정과 집계

- 미실행: 실제 요청을 보내지 않았거나 운영 연결·승인·안전한 시험 대상이 없습니다.
- 확인 불가: 보냈으나 응답·요청 ID·시각·서버 대조 중 하나라도 확인하지 못했습니다.
- 실패: 실측 결과가 기대와 다릅니다. 실패한 정상 요청을 거부 성공으로 집계하지 않습니다.
- 실측 통과: 실제 요청·정확한 상태/사유·응답 추적 번호·확인 시각·가린 서버 기록이 모두 일치합니다.
  정상 요청은 허용, 금지 요청은 거부여야 합니다. 오류 500/503을 기대한 401/403/404 거부로 대신 인정하지 않습니다.

한 시험에 여러 요청이 필요하면 각 요청별 영수증을 보관하고 모두 충족해야 해당 행을 통과로 집계합니다.
설치·오프라인 시험의 화면 확인은 HTTP 영수증과 별도 증거이며 API 응답만으로 설치 성공을 확정하지 않습니다.
6〜9단계는 기존 로컬 시험 통과를 운영 엔진 실측으로 쓰지 않습니다. 실제 재인증·회수 집행·복구 버전
연결이 없으면 계속 미실행입니다. 공지 저장소의 501은 정상 공지 조회의 실측 통과가 아닙니다.

집계는 고유 시험 ID 기준으로 하며 재시도 횟수를 시험 종류 수로 더하지 않습니다. 정상과 금지 모두
실측 영수증이 있어야 종합 완료로 표시합니다. 미실행을 통과로 계산하거나 예상 결과로 실제 열을 채우지 않습니다.

## 이번 변경 확인

`node --test test/operations-summary.test.mjs`는 표 초기값과 노출 방지를 확인하는 모의 시험입니다.
실제 41종 요청은 실행하지 않습니다. 배포 후 로그인·기기 승인 → **작전실 요약 새로고침**에서
표와 동일한 기록 번호의 `operations_summary` 서버 로그를 대조합니다. 이 요약 대조도 41종 실측을 대신하지 않습니다.
